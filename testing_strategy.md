# Testing Strategy

## Test Markers

Use markers to keep default tests fast and portable:

- default: Python-only tests.
- `reddyproc`: tests requiring R, REddyProc, and `rpy2`.
- `integration`: larger case-study or file-based tests.
- `slow`: long-running comparisons.

Default CI should run Python-only tests. R-backed tests are opt-in.

## Data-Backed Test Fixture Policy

For all future tests that require real eddy covariance data, use the case-study
datasets under `01_data/case_study`:

- flux data: `01_data/case_study/flux/flux.csv`
- biomet data: `01_data/case_study/biomet/biomet.csv`

These files contain multiple sites in one table. Unless a test is explicitly
about site-selection behavior, tests must filter both files to:

```text
site_id == "RBMNN"
```

before stage-1 loading, stage-2 preparation, backend execution, or scientific
comparison. Do not run package tests against the combined two-site frame because
duplicate timestamps across sites would mix independent towers.

The current case-study files use a flattened export shape:

- `timestamp` instead of legacy `date` + `time`.
- `u_star` instead of legacy `u.`.

Future data-backed tests should either use a package adapter that supports this
shape directly or create an explicit temporary adaptation in the test setup. Do
not rewrite or overwrite the raw case-study files.

## Milestone 1 Tests

Required:

- Legacy import tests.
- Legacy stage-1 eddy tests.
- Legacy hesseflux fixed-mode tests.

Rule: do not change expected behavior in this milestone.

## Milestone 2 Tests

Required:

- Stage-2 preparation returns required columns.
- `Year`, `DoY`, and `Hour` are computed correctly.
- Negative `Rg` is clamped to zero.
- `USTAR` maps to `Ustar` for REddyProc input.
- Missing required columns produce clear errors.

## Milestone 3 Tests

Required:

- Missing `rpy2` or R produces actionable skip/error behavior.
- Backend output contains all required common columns.
- Backend diagnostics include u* scenarios and selected scenario.
- A tiny synthetic or fixture dataset can exercise the adapter where R is
  available.

Recommended:

- Optional parity fixture generated from `R_manglaria.R`.

## Milestone 4 Tests

Required:

- Fixed mode still uses explicit caller threshold.
- Dynamic mode does not read or default to the old arbitrary fixed threshold.
- Dynamic mode produces u* diagnostics.
- Low nighttime `USTAR` values are filtered before NEE gap filling.
- Sparse nighttime data fail explicitly.
- Lasslop partitioning path returns finite GPP and Reco where inputs permit.
- Any data-backed integration test uses `01_data/case_study` filtered to
  `site_id == "RBMNN"`.

## Milestone 5 Tests

Required:

- R environment preflight runs before any live `reddyproc-rpy2` comparison and
  records R executable or launch path, `R.home()`, R version, `.libPaths()`,
  `REddyProc` version, and `rpy2` version.
- Live R tests must not silently use an arbitrary global R installation. If no
  controlled or explicitly approved R environment is available, the preflight
  must stop with an actionable skip/failure before scientific comparison.
- Case-study pipeline can run end-to-end for both available backends using the
  `RBMNN` subset of `01_data/case_study`.
- Comparison report includes:
  - u* threshold scenarios.
  - NEE_f coverage.
  - GPP and Reco summary statistics.
  - daily totals.
  - aggregate carbon balance.
  - correlations and bias against REddyProc-backed output.

## Acceptance Philosophy

Use exact assertions for schema, configuration, and deterministic transformations.
Use tolerances for scientific numeric comparisons between REddyProc and hesseflux.

Never approve a change solely because plots look reasonable. Plots are supporting
evidence; tests and diagnostics are required.

## M001-S01 Synthetic Fixtures and Verification Lanes

The excluded raw fixtures `tests/data/full_output/full_output.csv` and
`tests/data/biomet/biomet.csv` are replaced by deterministic synthetic files
generated by `tests/synthetic_eddy.py` (45 days, seed `20261021`, legacy
EddyPro shape with a `[HH:MM]` unit row). The generator uses solar geometry,
Lloyd-Taylor respiration, a Lasslop light response with VPD limitation and a
u* attenuation threshold, so partitioning has a real signal.
`tests/test_m001_s01_synthetic_fixtures.py` pins the committed bytes to the
generator and requires at least 48 paired finite GPP/Reco rows with no
partition-failure warning. No real observations are used.

Diagnosis recorded in M001-S01: the intake partition-failure warning under
numpy 2.5.4 / pandas 2.3.3 / scipy 1.18.1 / hesseflux 5.0 came from fixture
suitability, not a dependency incompatibility. On the linear
light-response frame built by the dynamic-u* unit tests, hesseflux 5.0's
Lasslop routine raises `AssertionError` while indexing its accepted-window
list (`djul[lii]` yields a scalar), which the engine reports as the
partition-failure warning with NaN GPP/Reco. The same runtime partitions the
physically structured fixture, so those versions are pinned
(`docker/constraints-py312.txt`) rather than changing science.

Full verification (check-only, scratch outside the repository):

```text
python 06_infra/verification/verify_integration.py --phase baseline
```

Lanes: frozen-baseline integrity; host runtime identity and candidate-source
identity; the portable suite under the retained-test guard; guard self-tests
on scratch copies; CLI-profile/frozen config parity and real hesseflux on the
frozen 120-day input with C2 comparison; and the Docker lane in the frozen
comparison runtime. The verifier never builds an image. A digest of every
lane is printed as the last lines of its output.

Retained-test guard (`06_infra/verification/pytest_guard.py`): every node id
in the frozen `01_data/baseline/test_ids_portable.json` (571 ids) must be
collected and pass, unless it is listed in `tests/retired_test_ids.json` with
the retiring slice id, a reason and optional replacement ids (replacements
must be collected and pass; entries for unknown or still-collected ids fail).
Every collected test must run and pass, so `-k`/`-m`/`addopts` deselection,
conftest removal, skips and xfails fail; zero collection, collection errors,
missing dependencies and a `miaproc` import outside `08_pkg/miaproc/src`
fail; new tests are allowed. Slices that delete or move frozen tests record
them in `tests/retired_test_ids.json`; they never edit the frozen list.
Self-tests show that deleting one test function, deleting `test_cli.py`,
`addopts` deselection, a missing dependency, skip/xfail, zero collection and
a retirement naming a missing replacement are rejected, and that a valid
retirement entry is accepted in a full run.

Frozen comparison runtime: container lanes run the image whose ID is
recorded in `01_data/baseline/runtime_container.json`, addressed by ID (never
by tag), with the candidate source mounted read-only: project-scoped R
preflight, seeded real REddyProc baseline comparison, the exact live-R module
against its frozen ids (preflight opt-in set, skip escape hatch unset), the
preflight module on POSIX (the Windows-only path-equivalence test must be
reported not applicable, never passed), the image's own tests resolving
`/app/06_infra/schemas`, isolated wheel build/install/`pip check`/console
help, distribution contents and separate silver/gold/readback CLI processes.
Drift of the tracked Dockerfile, `constraints-py312.txt` or `renv.lock` from
the recorded build-input hashes is reported, not failed: the product image
(`docker build ... -t miaproc-eddy-parquet:product-local 08_pkg/miaproc`) may
evolve, but comparisons stay in the frozen runtime. If the frozen image is
absent the verifier fails closed; a rebuild cannot recreate it, so restoring
comparisons needs an architect re-baseline decision. Only
`test_eddy_reddyproc_live.py` (container lane) and the private
`test_case_study_integration.py` (not run) are separate lanes.

Same-engine comparisons require identical column order, keys, timestamps,
text values and missing-value masks; floats use `rtol=1e-7, atol=1e-9`.
The frozen baseline lives in `01_data/baseline/` and is written once by
`06_infra/verification/record_baseline.py`; later slices only read it.

## M001-S03 Installed-Package and Product-Image Verification

Full M001 verification (check-only; never builds or tags an image):

```text
python 06_infra/verification/verify_integration.py --phase M001
```

It runs every `--phase baseline` lane, then the product image lane. The
product image is recorded in `06_infra/verification/product_image.json`
(image ID, build argv, build-input hashes, baked-content hashes and runtime
identity) by `06_infra/verification/record_product_image.py`, which performs
the one Docker build; the verifier addresses the image by that ID only.

- Product runtime build inputs (Dockerfile instruction lines, its ignore
  file, `constraints-py312.txt`, `renv.lock`) must equal the record; a
  comment-only Dockerfile edit is reported, not failed. Content baked into
  the image (`src`, `tests`, `docs`, ...) is compared with the candidate and
  reported only: the current candidate is what executes, from a freshly
  built wheel, so a test- or doc-only change needs no rebuild.
- Inside the image (`--network none`, candidate mounted read-only): runtime
  identity and dependency pins equal the record (every installed
  constraints entry exact, every `renv.lock` record exact, apt list
  reported); the baked install answers `miaproc`, `eddy`, `run-silver` and
  `run-gold` help without biomass, refuses `import miaproc.biomass` and
  passes the project-scoped R preflight; the candidate source passes the
  preflight; the baked layout tests (lineage schemas, Dockerfile extras,
  removed surfaces, grouped user path) pass under the guard; a candidate
  wheel is built, content-checked (no biomass modules/assets/extra),
  installed without dependencies in an isolated venv (`pip check`, help,
  import and installed-file checks) and its installed CLI runs the
  documented two-site user path in fresh processes: `run-silver`, `run-gold`
  with `hesseflux-native` and with `reddyproc-reference` (R console scanned
  for partition-failure markers), a `reddyproc-reference` run refused with
  exit 2 and no output under a repo root without the project-scoped R, and a
  separate readback process (`06_infra/verification/user_path_readback.py`)
  that checks per-site rows, group stacking, column preservation, paired
  finite GPP/Reco >= 48 per site and engine, persisted diagnostics files and
  run JSONs.
- The host portable suite also runs the grouped silver -> gold
  (`hesseflux-native`) path in separate processes of the editable source
  (`tests/test_m001_s03_user_path.py`), on a shorter two-site input.

Guard hardening in M001-S03 (both phases): a `--collect-only` run fails
unless the verifier's own self-tests allow it; every guarded lane must show
`passed + not_applicable == collected > 0`; `PYTEST_ADDOPTS` is not passed to
guarded lanes; the frozen `required_modules` of `test_ids_portable.json` must
each contribute passing tests, so retiring a whole core eddy module fails
even with valid retirement entries. New self-tests prove a collect-only run
and a fully retired required module are rejected, and a table-driven check
proves the built-wheel biomass check fires on biomass modules, packaged data
assets and a `biomass` extra.

Multi-site synthetic input: `python tests/synthetic_eddy.py OUT --site
SITE_A:120:20261101 --site SITE_B:105:20261102` writes one flux and one
biomet CSV per site with a `site_id` column and no unit row (a unit row would
become its own `--group-column` category). The single-site default output is
unchanged and remains pinned by `tests/test_m001_s01_synthetic_fixtures.py`.

## M002-S05 Product Image and Docker Mount Verification

The development project's full command since M002-S05 is (repository root of
the development project; the verification scripts are not part of the
package):

```text
python 06_infra/verification/verify_integration.py --phase M002
```

It runs every `--phase baseline` lane (the milestone obligation modules
`test_m001_s02_removed_surfaces.py`, `test_m001_s03_user_path.py`,
`test_m002_s02_parquet_io.py`, `test_m002_s03_publication.py`,
`test_m002_s04_bigquery_removed.py`, `test_m002_s04_payload_regressions.py`
and `test_m002_s05_package_docs_inputs.py` are additional required modules
of the portable lane), then three lanes in the Google-free product image
recorded by the one M002-S05 build (addressed by image ID; build-input drift
or a missing image fails closed): the product image lane described above;
the Google-free lane inside the product image (the image interpreter imports
no Google/gRPC/protobuf/db-dtypes module, freeze and site-packages hold
none, a logged blocker control import precedes the installed-wheel
processes); and the Docker mount user path of
[`docker/README.md`](docker/README.md) in fresh `docker run --rm --network
none` processes with the current source mounted read-only over the image's
editable install: read-only input, separate writable output and scratch
mounts, silver, gold with both engines, R preflight, `validate-run`, a
separate reader process and the rejection of copied runs with a removed
manifest, a truncated table or a missing gold artifact (exit 3, nothing
written). `--phase M001` refers to the superseded M001-S03 product record
and fails closed on build-input drift by design.
